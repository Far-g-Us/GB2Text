# Как внести вклад в GB2Text

Спасибо, что хотите внести свой вклад в GB2Text — инструмент извлечения текста из ROM! Этот документ объясняет, как вы можете помочь в развитии проекта, соблюдая юридические ограничения.

## ⚠️ Важное юридическое предупреждение

**Прежде чем вносить вклад, ознакомьтесь с нашим [LICENSE](../../LICENSE.md)**.

Этот проект:
- НЕ содержит и НЕ распространяет никакие ROM-файлы коммерческих игр
- Предназначен ТОЛЬКО для использования с законно принадлежащими вам ROM-файлами (homebrew или законно приобретёнными)
- НЕ должен использоваться для содействия несанкционированному копированию или распространению защищённого авторским правом контента

**Нарушение этих правил приведет к отклонению вашего вклада и возможному удалению из проекта.**

## Как безопасно вносить вклад

### 1. Конфигурационные файлы (`plugins/config/`)

- **ДОПУСТИМО** добавлять конфигурации для:
  - Игр, ROM-файлы которых принадлежат вам на законных основаниях (homebrew или коммерческие)
  - Общих примеров, демонстрирующих формат конфигурации

- **НЕДОПУСТИМО** добавлять:
  - Любой защищённый игровой текст, диалоги или ассеты
  - ROM-файлы, дампы ROM или ссылки на скачивание ROM
  - Инструкции по приобретению ROM-файлов, которыми вы не владеете на законных основаниях

- **Пример безопасной конфигурации**:
  ```json
  {
    "game_id_pattern": "^MY_HOMEBREW_[A-Z0-9]+_[0-9A-F]{2}$",
    "segments": [
      {
        "name": "main_text",
        "start": "0x4000",
        "end": "0x5000",
        "charmap": {
          "0x20": " ",
          "0x41": "A",
          "0x42": "B",
          "0xFF": "[END]"
        }
      }
    ]
  }
  ```

### 2. Таблицы символов и кодировки

- **ДОПУСТИМО** добавлять:
  - Базовые ASCII символы (A-Z, a-z, 0-9, пунктуация)
  - Общие японские символы (хирагана, катакана) без привязки к конкретным играм
  - Сопоставления символов, восстановленные из игр, чьи ROM-файлы принадлежат вам на законных основаниях (только смещения и кодировки, без извлечённого текста диалогов)

- **НЕДОПУСТИМО** добавлять:
  - Извлечённый текст диалогов или названия предметов из коммерческих игр
  - Полные данные ROM или любой защищённый ассет

### 3. Руководства (guides/)

- **ДОПУСТИМО** создавать руководства:
  - По настройке и использованию инструмента
  - По методикам реверс-инжиниринга на собственных законно принадлежащих вам ROM-файлах

- **НЕДОПУСТИМО** создавать руководства:
  - По работе с неавторизованными копиями ROM
  - Воспроизводящие защищённый игровой контент

## Процесс внесения изменений

### 1. Создайте issue перед началом работы
- Обсудите, соответствует ли ваша идея юридическим требованиям проекта
- Убедитесь, что ваш вклад не нарушает авторские права

### 2. Создайте ветку для вашей работы

```bash
git checkout -b feature/your-feature-name
```

### 3. Следуйте стандартам кода
- Добавляйте юридическое предупреждение в начало каждого файла
- Пишите понятные комментарии на английском
- Сохраняйте стиль кода, единый с существующей кодовой базой
- Добавляйте тесты для новой функциональности

### 4. Создайте Pull Request
- Четко объясните, как ваш вклад соответствует юридическим требованиям
- Укажите, какие игры (если есть) поддерживаются вашим вкладом
- Подтвердите, что вы соблюдаете все правила из этого документа
- Включите тесты для новой функциональности, где это применимо

## Тестирование изменений

Перед отправкой PR запустите тестовый набор:

```bash
pytest tests/ -v
```

Для быстрого локального запуска без тяжелых интеграционных тестов,
сканирующих ROM-файлы:

```bash
pytest tests/ -m "not slow"
```

Для распараллеливания тестов по ядрам CPU (рекомендуется для полного набора):

```bash
pytest tests/ -n auto
```

Покрытие измеряется в CI (workflow `coverage.yml`). Локально `--cov`
запускайте только когда нужно отчёт:

```bash
pytest tests/ -m "not slow" --cov=core --cov=plugins
```

## 🐞 Отладка и диагностика

Если вы столкнулись с проблемой, пожалуйста, соберите диагностическую информацию перед созданием issue:

1. Убедитесь, что у вас установлена утилита `sha1sum` (обычно входит в пакет coreutils)
2. Запустите диагностический скрипт:
```bash
chmod +x scripts/diagnostics.sh
./scripts/diagnostics.sh your_file.gb
# или на Windows:
scripts\diagnostics.bat your_file.gb
```
3. Приложите полученный каталог к вашему issue на GitHub

Это значительно ускорит процесс решения проблемы.

## Примеры безопасного вклада

**Хорошие примеры:**
- Добавление поддержки нового типа сжатия (без привязки к конкретным играм)
- Улучшение алгоритма автоматического определения таблицы символов
- Создание шаблона для плагинов домашних игр
- Исправление ошибок в базовой логике извлечения/вставки
- Улучшение покрытия тестами
- Добавление нового языка в интерфейс
- Добавление плагина игры с проверенными смещениями/кодировкой для ROM, который принадлежит вам на законных основаниях (без включения извлечённого текста)

**Плохие примеры:**
- Включение извлечённых диалогов или защищённого текста в репозиторий
- Включение ROM-файлов или ссылок на их скачивание
- Создание руководств по работе с неавторизованными копиями игр
- Добавление защищённого текста диалогов в репозиторий

> 2. Предназначен ТОЛЬКО для использования с законно принадлежащими мне ROM-файлами

> 4. Соответствует всем требованиям, изложенным в LICENSE и этом документе"

## Стиль кода

- Совместимость с Python 3.11+
- Используйте аннотации типов где уместно
- Следуйте рекомендациям PEP 8
- Запустите `ruff check .` перед отправкой
- Добавляйте docstring к публичным функциям и классам
