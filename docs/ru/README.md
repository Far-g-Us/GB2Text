# GB2Text

[![License](https://img.shields.io/badge/License-Custom-blue.svg)](../../LICENSE.md)
[![Python](https://img.shields.io/badge/Python-3.11-blue)](https://python.org)

**Инструмент GB Text Extraction** — универсальный инструмент для извлечения и перевода текста из файлов Game Boy, Game Boy Color и Game Boy Advance ROM с поддержкой плагинов.

## ⚠️ Правовая оговорка

**Этот проект предназначен только для анализа файлов ROM, которые принадлежат вам на законных основаниях.** 
Вы должны использовать этот инструмент ТОЛЬКО с ROM-файлами homebrew, которые вы создали самостоятельно, или с коммерческими ROM-файлами, приобретенными вами на законных основаниях.

Nintendo, Pokémon, The Legend of Zelda и все связанные с ними торговые марки являются собственностью их соответствующих владельцев.

**Этот проект не содержит и не распространяет какие-либо коммерческие файлы ROM.**

## 🚀 Особенности

- Извлечение текста из файлов GB, GBC и GBA ROM
- Графический интерфейс для удобного редактирования и перевода текста
- Поддержка пользовательских карт символов
- Автоматическое определение сегмента текста
- Ввод текста обратно в файлы ROM
- Система плагинов для конфигураций, специфичных для игры
- Поддержка нескольких языков (английский, японский, русский)

## 🧩 Создание пользовательских конфигураций 

#### Этот инструмент предназначен для работы с файлами ROM, которые принадлежат вам на законных основаниях. Чтобы создать конфигурацию для вашей игры: 

- Запустите графический интерфейс с помощью `python main.py --gui`
- Загрузите свой файл ROM
- Используйте кнопку "Создать конфигурацию" на вкладке "Настройки"
- Сохраните конфигурацию в каталоге `plugins/config/`

Не добавляйте статические конфигурации для конкретных игр в каталоге `plugins/config/` в репозиторий без одобрения мейнтейнеров. Плагины игр (`.py`) следуют процессу из [ВКЛАДА](CONTRIBUTING.md).

### Пример структуры конфигурации:
```json
{
  "game_id_pattern": "^HOME_BREW_[A-Z0-9]+_[0-9A-F]{2}$",
  "segments": [
    {
      "name": "main_text",
      "start": "0x4000",
      "end": "0x5000",
      "charmap": {
        "0x20": " ",
        "0x41": "A",
        "0x42": "B",
        "0xFF": "[END]"
      }
    }
  ]
}
```

## 🧩 Плагины сообщества и пользовательские шрифты

#### Плагины определяют ROM-специфичную раскладку игры: смещения текста, таблицы указателей, чармапы и кодировки — ни игрового текста, ни защищённого копирайтом контента в этом репозитории нет.

- **Конфиги плагинов сообщества** (`*.json` в `plugins/config/`): только числовые структуры ROM (смещения, free-after размеры, смещения указателей). Статические конфиги под конкретную игру принимаются строго через процесс [CONTRIBUTING](CONTRIBUTING.md).
- **Установка плагинов** — диалог **Community Plugins** в GUI или Agent API (команда `plugins`). Реестр принимает только HTTPS-загрузки с заранее одобренных хостов; каждый файл проверяется лимитом размера, SHA-256-контрольной суммой и строгой схемой ответа (`{"ok": bool, ...}`). JSON-конфиги плагинов валидируются (`game_id_pattern` + `segments`) перед установкой.
- **Скрининг вирусов / вредоносного контента многослоен**: JSON-конфиги плагинов валидируются и хранятся как данные (числовые структуры: смещения, контрольные суммы проверяются перед использованием); Python-плагины ставятся как код и исполняются при загрузке, поэтому всегда проверяйте сторонние конфиги перед инжекцией. Код плагина выполняется только для игр, которыми вы законно владеете; песочницы нет.

### Пользовательский шрифт / кодировка (.tbl/.json чармапы)

- **Таблицы шрифтов** ставят в соответствие сырым байтам символы. Вы можете поставить свой `charmap` (по языку: ASCII, катакана/хирагана, кириллица).
- Добавляйте глифы, расширяя `charmap` в конфиге плагина; неизвестные байты декодируются как hex-токены `{{XX}}` .
- GUI: **Настройки → Таблица символов** позволяет грузить/сохранять `.tbl` чармапы и тестировать кодирование/декодирование вживую.

## 🌐 Поддержка нескольких языков 

#### Инструмент поддерживает несколько типов кодировок:

## 🤖 API для агентов / Автоматизация

Модуль `api/` предоставляет программный доступ для агентов, скриптов и headless-сценариев — три интерфейса с единым контрактом:

| Интерфейс | Точка входа | Примечания |
|-----------|-------------|------------|
| **Python SDK** | `from api import _core` (REPL / Jupyter) | `resolve_rom`, `detect`, `extract`, `inject`, `diff_roms`, `list_plugins`, `get_version`, `load_json_file` |
| **CLI** | `python -m api.cli <command> --json` | Подкоманды: `plugins`, `detect`, `extract`, `inject`, `serve` — коды выхода 0/1/2 |
| **HTTP / JSON** | `python -m api.cli serve` (по умолчанию 127.0.0.1:8080) | Эндпоинты: `/health`, `/plugins`, `/detect`, `/extract`, `/inject`, `/diff` — лимиты размера, таймаут, 503 BUSY |

Все три возвращают стабильную схему ответа: `{"ok": bool, "data": ... | "error": {"code", "message"}}`.

Полный контракт, дизайн безопасности и примеры: **[API_AGENTS.md](API_AGENTS.md)**.

### 🛡️ Рекомендации по юридической безопасности 

#### Этот проект соответствует строгим юридическим принципам: 

- Коммерческие ROM-файлы не включены
- Плагины задают только смещения и кодировки; защищённый игровой текст в репозитории не хранится
- `core/manifests/*.json` содержат только числовые структуры ROM (адреса строк, размеры free_after, смещения указателей), созданные локально из вашего собственного легального ROM скриптом `scripts_roms/generate_manifest.py`; без текста игры, ассетов или кода
- Документируйте/настраивайте только ROM-файлы, которыми вы владеете на законных основаниях
- Во всей документации четко указаны юридические оговорки
