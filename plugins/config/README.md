# Конфигурации плагинов

JSON-конфигурации для поддержки конкретных игр.

## Шаблоны

| Файл | Платформа | Описание |
|------|-----------|----------|
| `_template_game.json` | Любая | Минимальный шаблон |
| `_template_gba.json` | GBA | Полный шаблон с паттернами |
| `_template_gb_basic.json` | GB/GBC | Базовый шаблон |
| `_template_gbc.json` | GBC | С расширенной кодировкой |
| `example.json` | GBA | Рабочий пример |

## Режимы извлечения

### ASCII (простой)
```json
{
  "encoding": "ascii",
  "terminators": ["0x00"],
  "min_length": 20
}
```
**Игры:** Sonic Advance, KH:CoM, Phoenix Wright

### ASCII + control codes
```json
{
  "encoding": "ascii_with_control_codes",
  "terminators": ["0x0D", "0x0A", "0xFF"],
  "control_codes": {"0x06": "\n", "0x0A": "\n"}
}
```
**Игры:** Castlevania AoS, Metroid Fusion

### Multi-byte (японский)
```json
{
  "encoding": "multi_byte",
  "primary_range": ["0xC2-0xD6"],
  "terminators": ["0x0D", "0xFF"]
}
```
**Игры:** FF5/FF4 Advance, FFTA

### Pointer table
```json
{
  "encoding": "pointer_table",
  "pointer_base": 134217728,
  "pointer_size": 4
}
```
**Игры:** FF5/FF4 Advance, Castlevania AoS

### Compressed (LZ77)
```json
{
  "encoding": "compressed",
  "header_byte": "0x10",
  "handler": "GBALZ77Handler"
}
```
**Игры:** Pokemon Gen 3

## Как создать плагин

1. Скопируйте шаблон
2. Определите `game_id_pattern` (regex для Game ID из заголовка ROM)
3. Выберите режим извлечения
4. Укажите адреса сегментов
5. Создайте charmap (таблицу символов)

## Как найти game_id

Откройте ROM в hex-редакторе:
- **GBA:** offset 192 (4 байта), например `BZ5E` = FF5 Advance
- **GB:** offset 308 (11 байт) = название, offset 304 (4 байта) = код

## Как найти текстовые сегменты

1. Запустите `python main.py` с ROM
2. Включите "Debug mode" для просмотра найденных сегментов
3. Определите терминатор (0x00, 0xFF, 0x0D, 0x50)
4. Проверьте min_length для фильтрации мусора

## Поля сегмента, которые меняют ЗАПИСЬ

Эти поля читает не только экстрактор — по ним инжектор решает, **что** и **куда**
записать. Ошибка здесь не исключение, а порча байт в ROM, поэтому значения
следует задавать осмысленно.

### `fixed_width`

Ширина слота в байтах. Сегмент трактуется как таблица слотов фиксированной
ширины; `room` для перевода — вся ширина слота, а не длина исходного текста.

Доступная длина перевода — `fixed_width - 1`: последний байт слота отведён под
границу записи. Перевод ровно по ширине отвергается.

**Игры:** Wario Land 4, Pokemon GBA (таблицы имён/типов), Pokemon Gen1/GSC.

### `pad_byte`

Байт заполнения слота. Им же инжектор добивает хвост, когда перевод короче
записи. Значение вне `0..255` или не-int **молча заменяется дефолтом**
(`0xFF` для fixed-слота, `0x20` иначе) — запись не потеряется, но паддинг будет
не тем.

Значение важно и для проверки читаемости: инжектор отказывает переводу, который
короче, чем прочитается обратно. Хвост из `pad_byte` при чтении срезается ДО
декодирования — так реально работает извлечение.

**Игры:** Wario Land 4 и Pokemon GBA (`0xFF`), Pokemon Gen1/GSC (`0x50`).

### `has_mid_alias` — для записей с внешними указателями

`true`, если **в середину** записи смотрит чужой указатель. Тогда extent записи
задаётся её разделителем, а он же служит паддингом, поэтому любое сокращение
затирает хвост, где начинается вторая запись, и та исчезает из манифеста.

Что делает инжектор:

- **без** `has_mid_alias` хвост слота забивается `pad_byte` — а если туда смотрит
  чужой указатель, запись под ним стирается молча;
- **с** флагом сокращение такой записи отвергается, и отказ виден в
  `last_mid_alias_report` (GUI показывает его в отчёте).

**Игры:** FF4/FF5 Advance. Цена измерена: 561 из 646 переводимых записей FF4
(86.8%) нельзя сократить — существенное ограничение для русской локализации.

Флаг работает и без `fixed_width`: у FF4/FF5 таких сегментов 561, и инжектор
отвергает им сокращение. Валидация сегментов это НЕ проверяет и не должна:
непротиворечивость «флаг без слота» невозможно отличить от законной комбинации,
а ложный отказ отверг бы рабочие записи.

Автоматически проверить наличие внешнего указателя в хвосте слота тоже нельзя
одним чтением полей: нужен разбор указателей.
`scripts_roms/fixed_mid_pointer_probe.py` сделал это по-настоящему — прошёл все
10 GBA ROM корпуса с fixed-сегментами (116 сегментов) и нашёл **0 подтверждённых
указателей в середину слота**. Все 22 кандидата оказались ложными, и это
показательно: в GBA ROM любое 32-битное окно с приличной вероятностью лежит в
диапазоне `0x08xxxxxx`, потому что код ARM полон таких immediates. Разобранный
пример (`Pokemon - Crown`, `0x1BCF0E4`): 20 соседних слотов подряд попадают в
диапазон указателей, но их значения чередуются (`0x9B881C0`, `0x821FFF1`,
`0x9B88290`, ...) — это переплетённые табличные данные с шагом `0xD0`. Проверка
«все окна подряд лежат в диапазоне указателей» этот случай принимала; отбрасывает
его проверка монотонности целей — при чередовании прогон через каждое окно
имеет длину 1, а не 20.

Вывод для автора плагина: на текущем корпусе `has_mid_alias` для fixed-слотов —
предосторожность, а не измеренная необходимость. Ставить его надо, если вы
видите в хвосте записи чужой указатель (или не можете исключить), но
автоматика тут не заменит разбора.

Проверить это по своей игре можно одной командой:

```
python -m api.cli audit ПУТЬ/К_ROM.gba
```

Она перебирает fixed-сегменты, ищет подтверждённые указатели в хвостах слотов и
печатает по каждому сегменту «нужен `has_mid_alias`» / «не нужен» с адресами
попаданий (`--json` для автоматизации). На чистом FireRed: 4 сегмента, ни одному
флаг не нужен. Сравнение — по монотонности целей, поэтому переплетённые данные
ложными срабатываниями не дают.

## Валидация

Параметры проверки качества извлечения:

```json
{
  "validation": {
    "min_alpha_ratio": 0.3,
    "max_unknown_bytes": 0.2,
    "check_terminators": true
  }
}
```

- `min_alpha_ratio` — минимальная доля букв (0.0-1.0)
- `max_unknown_bytes` — максимальная доля неизвестных байтов
